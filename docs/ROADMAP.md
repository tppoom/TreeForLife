## 0. สรุปสำหรับคนรีบ

- โค้ดตอนนี้คือ **Phase 1 เวอร์ชันเดโม**: หน้าร้าน ค้นหา หน้าต้นไม้ สวนของฉัน ตัวคำนวณรอบรดน้ำ และ LINE handoff ใช้งานได้จริงและผ่านเทสต์
  แต่สิ่งที่ทำให้ **ลูกค้ากลับมา** (แจ้งเตือน) · **ร้านใช้ได้จริง** (หลังบ้านแก้ข้อมูล/อัปรูป) · **ปลอดภัยพอเปิดสาธารณะ** (ล็อกอินจริง ตรวจสิทธิ์) ยังไม่มี
- ลำดับที่เสนอ: **M1 ปลอดภัย → M2 ร้านใช้ได้จริง → M3 ลูกค้ากลับมา → M4 ซื้อซ้ำและบอกต่อ → M5 วัดผล** รวม ~10–12 สัปดาห์ที่ 10–12 ชม./สัปดาห์
- ต้นทุนระบบรวมทุก milestone: **~0–700 บาท/เดือน** (ตัวแปรหลักคือ Vercel Pro ถ้าใช้เชิงพาณิชย์ และโควตาข้อความ LINE)
- ฟีเจอร์ใหม่ที่ **คุ้มที่สุด** และไม่อยู่ใน SPEC เดิม: **ป้าย QR ติดกระถาง (F05)** — ต้นทุนเกือบศูนย์ แต่เชื่อมลูกค้าหน้าร้านเข้าระบบ วัดยอดซื้อซ้ำได้ และเป็นเหตุผลให้คนกลับมาทุกวัน

## 2. หลักคิดในการเลือกฟีเจอร์

### 2.1 วงจรที่ต้องหมุนให้ได้ (Growth loop)

```
   ┌──────────────── ค้นเจอบน Google / ได้ป้าย QR จากร้าน / เพื่อนส่งลิงก์ ────────────────┐
   │                                                                                        │
   ▼                                                                                        │
[1 ใช้]  ได้คำตอบเรื่องต้นไม้ทันที + เพิ่มต้นเข้าสวน ได้ตารางดูแลที่ "เข้ากับบ้านฉัน"          │
   │                                                                                        │
   ▼                                                                                        │
[2 กลับมา]  แจ้งเตือนวันละ ≤1 ครั้ง → กด "รดแล้ว" 2 วินาที → เห็นต้นโต (บันทึกรูป)         │
   │                                                                                        │
   ▼                                                                                        │
[3 ซื้อซ้ำ]  ถึงรอบเปลี่ยนกระถาง/ปุ๋ย · ของที่อยากได้เข้าร้าน · ต้นมีปัญหาแล้วร้านช่วย        │
   │         ทุกทางจบที่ LINE ร้านพร้อม ref code (ไม่มีตะกร้า ตามหลัก P1)                    │
   ▼                                                                                        │
[4 บอกต่อ]  แชร์การ์ดต้นไม้/สวน · ส่งลิงก์ต้นไม้ให้เพื่อนพร้อมโค้ดแนะนำ ─────────────────────┘
```

**ทุกฟีเจอร์ในเอกสารนี้ต้องดันขั้นใดขั้นหนึ่ง** ถ้าไม่ดันขั้นไหนเลย = ตัดทิ้ง

### 2.2 ชู value ของร้าน — ของที่คู่แข่งลอกไม่ได้

1. **รูปจริงที่ถ่ายที่ร้าน** (P6) — ลูกค้ารู้ว่าของมีจริง
2. **"ที่ร้านบอกว่า"** — ความรู้จากประสบการณ์จริง อยู่ทุกหน้าต้นไม้และทุก task
3. **สต็อกจริง** — สถานะของตรงกับร้าน แจ้งเมื่อของเข้า
4. **คนจริงตอบใน LINE** — ทุกหน้าจอมีทางออกไปหาร้าน พร้อมบริบทที่ร้านไม่ต้องถามซ้ำ
5. **ดูแลหลังการขาย** — ต้นที่ซื้อจากร้านได้การติดตามพิเศษ (F06) → เหตุผลที่ควรซื้อที่นี่ ไม่ใช่ที่อื่น

### 2.3 เกณฑ์ให้คะแนน

| มิติ | คำถาม |
|---|---|
| **Value** (1–5) | ดันวงจรข้อ 2.1 แรงแค่ไหน · ชู value ร้านข้อ 2.2 ไหม |
| **Cost/เดือน** | ค่าใช้จ่ายที่เพิ่มขึ้นจริง (บาท) ที่ ~500 ผู้ใช้/เดือน |
| **Effort** | ชั่วโมงทำงาน (ประมาณ) |
| **Risk** | ถ้าไม่ทำ จะเกิดอะไร |

## 4. Milestones

### M1 — ปลอดภัยพอเปิดสาธารณะ (สัปดาห์ 1)
F00 + F11 · **ปลดล็อก**: ส่งลิงก์ให้ลูกค้าจริงได้โดยไม่เสี่ยง
เกณฑ์ผ่าน: ไม่มี endpoint ไหนแก้ข้อมูลของคนอื่นได้ · มีหน้านโยบาย · ไม่มี role switcher เดโมใน production

### M2 — ร้านใช้ได้จริง + ค้นเจอบน Google (สัปดาห์ 2–4)
F01 + F04 + F13 · **ปลดล็อก**: ที่บ้านเริ่มถ่ายรูปและแก้ข้อมูลเองได้ · เปลี่ยนรูป Unsplash เป็นรูปจริงครบ 30 พันธุ์
เกณฑ์ผ่าน: ที่บ้านเพิ่มพันธุ์ใหม่พร้อมรูปจากมือถือได้เองใน ≤5 นาที (SPEC §6.9)

### M3 — ลูกค้ากลับมาเอง (สัปดาห์ 5–8)
F02 + F03 (+ เริ่มเก็บ event ของ F12) · **ปลดล็อก**: ระบบเตือนรดน้ำ = เหตุผลที่ต้องเปิดเว็บทุกวัน
เกณฑ์ผ่าน: แจ้งเตือนส่งจริงทั้ง Web Push (Android + iPhone PWA) และ LINE · ไม่เกิน 1 ข้อความ/คน/วัน

### M4 — ซื้อซ้ำและบอกต่อ (สัปดาห์ 9–11)
F05 + F06 + F07 + F08 + F09 · **ปลดล็อก**: ทุกต้นที่ขายออกจากร้านกลายเป็นช่องทางติดต่อระยะยาว

### M5 — วัดผลและตัดสินใจ Phase 2 (สัปดาห์ 12 + ต่อเนื่อง)
F12 (หน้าสรุป) + F10 ถ้ามีเวลา · ใช้ตัวเลขตัดสินตามภาคผนวก A ของ SPEC

## 5. การตัดสินใจทางสถาปัตยกรรม (ADR ย่อ)

| # | การตัดสินใจ | เหตุผล | ทางเลือกที่ไม่เลือก |
|---|---|---|---|
| ADR-01 | **Supabase = Postgres + Storage เท่านั้น** เชื่อมผ่าน `DATABASE_URL` (Supavisor pooler) ใช้ `pg` + Drizzle เหมือนเดิม | โค้ดเดิมไม่ต้องเปลี่ยน · Storage ฟรี 1GB พอสำหรับรูปพันธุ์และรูปผู้ใช้ที่บีบแล้ว | `supabase-js` ทั้งระบบ (ต้องรื้อ service layer) · Vercel Blob (อีกเจ้าให้ดูแล) |
| ADR-02 | **Auth = LINE Login (OAuth 2.1/OIDC) ทำเอง** + session cookie `httpOnly` เซ็นด้วย `jose` (HS256, `SESSION_SECRET`) | ลูกค้าไทยใช้ LINE · ได้ `line_user_id` ไปส่งแจ้งเตือนต่อ · ไม่มี vendor lock | Supabase Auth / NextAuth (เพิ่มชั้นโดยไม่ได้อะไร) |
| ADR-03 | **Schema เปลี่ยนแบบ additive เท่านั้น** ผ่าน `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` ต่อท้าย `SCHEMA_DDL` | `CREATE TABLE IF NOT EXISTS` **ไม่เพิ่มคอลัมน์ใหม่ให้ตารางที่มีอยู่แล้วใน production** — ถ้าลืมข้อนี้ เว็บจะพังทันทีที่ deploy | drizzle-kit migrations (ขัดกับกติกา dual DDL ที่ใช้อยู่) |
| ADR-04 | **Cron = Vercel Cron** เรียก `/api/cron/*` ป้องกันด้วย `CRON_SECRET` · ทุกงาน idempotent | ฟรีบน Hobby (วันละครั้งต่องาน) · ไม่ต้องมีเซิร์ฟเวอร์ | Supabase pg_cron (ตรรกะแยกจากโค้ดแอป) |
| ADR-05 | **Web Push เป็นช่องทางหลัก, LINE เป็นสำรองที่มีเพดาน** | Web Push ฟรีไม่จำกัด · LINE OA มีโควตาข้อความฟรีจำกัดต่อเดือน | LINE อย่างเดียว (โควตาหมดเร็ว) |
| ADR-06 | **ไม่ใช้ Supabase Realtime / Edge Functions / RLS เป็นกลไกหลัก** — สิทธิ์ตรวจในโค้ด server (`lib/auth/guard.ts`) และปิด Data API ของ Supabase | มีจุดตรวจสิทธิ์จุดเดียว เทสต์ได้ใน Vitest + PGlite | RLS (ต้องใช้ JWT ของ Supabase Auth) |

## 7. ตัวชี้วัด (ผูกกับภาคผนวก A ของ SPEC)

## 8. Definition of Done (ใช้กับทุกฟีเจอร์)

1. ทำครบ **เกณฑ์ยอมรับ** ในไฟล์ฟีเจอร์นั้น
2. ถ้าแตะ schema: แก้ **ทั้ง** `db/schema.ts` และ `lib/db/schema-ddl.ts` (ใช้ skill `sync-schema-ddl`) และเป็นแบบ additive ตาม ADR-03
3. ข้อความ UI ทุกคำอยู่ใน `lib/i18n/translations.ts` ทั้ง `th` และ `en` · มี `dark:` ครบ · ปุ่ม ≥44px · สถานะมีไอคอน+ข้อความ ไม่ใช่สีอย่างเดียว
4. เทสต์ใหม่ใน Vitest ผ่าน + `make verify` ผ่าน (typecheck + test + build)
5. Endpoint ที่เขียนข้อมูล: ผ่าน `requireOwner`/`requireStaff` + validation (zod) + rate limit
6. อัปเดต `docs/PROGRESS.md` และตาราง gap ในเอกสารนี้
7. ตั้ง env ใหม่ครบใน `.env.example` และ Vercel (ดู [`DEPLOYMENT.md`](./DEPLOYMENT.md))
