# F11 — PDPA: นโยบาย · ความยินยอม · ลบ/ดาวน์โหลดข้อมูล

> Milestone **M1** (หน้านโยบาย + guest) · ส่วนบัญชีทำพร้อม F02 · Effort ~6 ชม. · Cost 0
> SPEC §9.1–9.2 · เกณฑ์เปิดตัว §11.3 "มีหน้านโยบายความเป็นส่วนตัว"

## 1. ทำไม

บังคับตามกฎหมาย (พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล 2562) และสร้างความเชื่อใจ — ร้านเล็กที่ประกาศชัดว่าเก็บอะไร เก็บนานแค่ไหน ลบได้ด้วยปุ่มเดียว ดูน่าเชื่อถือกว่าเว็บใหญ่หลายเว็บ

> ⚠️ เนื้อหานโยบายในเอกสารนี้เป็นร่างทางเทคนิค **ให้ผู้รู้ด้านกฎหมายตรวจก่อนเผยแพร่**

## 3. ดาวน์โหลดข้อมูล — `GET /api/account/export`

JSON เดียว: `users` (ไม่มี field ภายใน) · `user_plants` · `care_tasks` · `care_logs` · `favorites` · `inquiries` · `aftercare_checkins` · `plant_photos` (signed URL อายุ 24 ชม.) · `notifications_log` 90 วัน · rate limit 3 ครั้ง/วัน · `Content-Disposition: attachment; filename="treeforlife-my-data-YYYY-MM-DD.json"`

## 4. ลบบัญชี — `POST /api/account/delete`

1. ยืนยัน 2 ขั้น (พิมพ์คำว่า "ลบ")
2. ทันที: `session_version++` (ออกจากทุกเครื่อง) · `deleted_at = now()` · ลบ `push_subscriptions` · หยุดแจ้งเตือนทุกช่องทาง
3. **Hard delete ภายใน 30 วัน** (cron `cleanup` F03 ทำทุกสัปดาห์กับแถวที่ `deleted_at < now() - 7 days`): ลบ user (cascade `user_plants` → tasks/logs/photos) · ลบ object ใน Storage · `inquiries.user_id` → NULL (เก็บสถิติไม่ระบุตัวตน, `payload` ลบฟิลด์ที่ระบุตัวบุคคล) · `care_tags.claimed_user_plant_id` → NULL
4. ช่วง 7 วันแรกล็อกอินกลับมา = ยกเลิกการลบได้ (แสดงแถบ "บัญชีกำลังจะถูกลบวันที่ …")

## 5. Retention อัตโนมัติ (cron `cleanup`)

| ข้อมูล | เก็บนาน |
|---|---|
| guest ที่ไม่มีกิจกรรม (ไม่มี task action / เข้าเว็บ) | 180 วัน แล้วลบ |
| `notifications_log` | 180 วัน |
| `rate_limits`, `line_events_seen` | 1–7 วัน |
| `events` (F12) | 13 เดือน แล้วเก็บแค่ยอดรวม |
| `inquiries` | ถาวร แต่ถอดตัวตนเมื่อผู้ใช้ลบบัญชี |

ต้องมี `guest_activity (guest_token PK, last_seen_at)` หรือใช้ `MAX(created_at)` จากตารางที่เกี่ยว — แนะนำตารางเล็กนี้ (อัปเดตไม่เกินวันละครั้งต่อ token)
